Saved sets keep each filter exactly as saved.

- `modules/graphql-router/src/schema/index.ts`, `config/utils/index.ts`: a sets index the GraphQL router creates maps each set's `sqon` as `enabled: false`, stored and never indexed. An existing sets index keeps the mapping it was created with; at startup the router names one that does not store filters as data in `sets.index_mapping_outdated`, at warn, or logs `sets.index_mapping_unchecked` where the engine will not show the mapping, and starts either way.
- `integration-tests/server/test/setsIndexMapping.test.ts`: on both engines, sets saved for filters of every shape are stored exactly as saved, and a router on an index created with the earlier mapping warns and serves.
- `docs/reference/08-Migration/v3.1.md`, `CHANGELOG.md`: the migration section for recreating a sets index created before 3.1, and its changelog entry.

A field the schema types as JSON is served whole, as stored.

- `modules/graphql-router/src/mapping/resolveHits.js`: hits map each field mapped `type: 'object'` to its stored value, never walking into it or coercing its lists, so a saved set's `sqon` reads back exactly as saved.
- `resolveHits.test.js`, `integration-tests/server/test/jsonFields.test.ts`: a catalogue's JSON field and a saved set's filter, single-value lists at several depths included, read back whole on both engines.
- `CHANGELOG.md`: its server entry.

A pivot group keeps every condition of each clause it merges.

- `modules/graphql-router/src/middleware/buildQuery/index.js`: `collapseNestedFilters` folds every condition a nested clause holds, under `must` and `must_not`, into its sibling on the same path, so a range given several bounds applies all of them to the same nested item, whichever position it holds in the group.
- `pivotedGroups.test.js`, `integration-tests/server/test/rangeBounds.test.ts`: such a range first and later in a pivoted `and` and `not`, on both engines, and a clause holding both kinds of condition.
- Integration runs from a worktree whose `node_modules` links to the main checkout's load the GraphQL router from that checkout's `dist`, so each full run builds that `dist` from the code under test first.

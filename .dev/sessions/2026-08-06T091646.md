Fixed a self-triggering rebuild loop in `modules/sqon`, reported by Rakesh Mistry (OHCRN) via `npm run dev:server` failing: an oversight in this session's own earlier `generateVersion.mjs` work (browser-bundling fix), which never checked the package's existing `watch` script before adding a new file-write side effect.

- Root cause: `generateVersion.mjs` (wired as `prebuild`/`pretest`) unconditionally rewrites `src/version/generated.ts` on every build; `sqon`'s `watch` script (`nodemon -w src -e ts --exec "npm run clear:dist && npm run build"`) watches that same directory, so the write retriggers the watcher, which reruns the build, which rewrites the file, forever. Confirmed `modules/types`'s own watch script (`nodemon -w src -w ../sqon/dist ...`) would have cascaded the loop into a second package too, likely why `dev:server` looked fully broken rather than just noisy.
- Fixed with two independent measures: `nodemon --ignore src/version/generated.ts` (direct fix for the known trigger) and made `generateVersion.mjs` idempotent, skip the write if content is unchanged (general-purpose defense, covers any other watcher that doesn't know to ignore this path). Verified empirically, not just reasoned through: ran the `watch` script in a bounded background window, triggered one real source change, confirmed exactly one rebuild cycle then quiescence, not a loop.
- Surveyed every watch/dev script in the monorepo to check how common this risk shape is; wrote up the incident, the full cross-package watch-chain map, and the generalized pattern in `.dev/docs/watch-loop-from-sqon-generateVersion.md`, explicitly as source material for a future agentics convention (same relationship `release-process.md` has to agentics).
- Diagnosed the gap in agentics' own conventions that let this happen: the existing "default review or audit posture" bullet (Interaction Parameters) is about adopting a skeptical *stance*, not about *scope*, it doesn't point a reviewer at a package's own watch/dev-loop scripts specifically, which aren't exercised by the normal act of verifying a build/test change works.

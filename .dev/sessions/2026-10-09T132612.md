Phase 0 of the MCP host plan starts with the SDK upgrade, and the plan settles two `mcp-client` design questions before any code exists.

- `apps/mcp-server/package.json`, `integration-tests/mcp-server/package.json`, `package-lock.json`, `CHANGELOG.md`: MCP SDK upgraded to 2.3.1 and `node` to 2.1.1, with every suite passing unchanged. 2.3.0's one-connection-per-server change does not reach `apps/mcp-server`, which gives `createMcpHandler` a per-request factory.
- `.dev/docs/mcp-host-plan.md`: the upgrade moves into Phase 0, since S2 and S5 test 2.3.1 behaviour.
- `.dev/docs/mcp-host-plan.md`: S1 sends schemas through `/v1/chat/completions`, the path the provider uses.
- `.dev/docs/mcp-host-plan.md`: host-core alone owns the confirmation timeout, since a second clock in `mcp-client` would race it.
- `.dev/docs/mcp-host-plan.md`: the surface hash is built from named fields and keeps each item's `_meta`. Stripping every `_meta` key was rejected because it would also delete an input-schema property of that name.
- `.dev/docs/mcp-host-plan.md`: new open question on thinking models' `reasoning` field, which Ollama's `/v1/chat/completions` returns and accepts back.
- `.dev/docs/mcp-host-plan.md`: Phase 0 names its models: three local, and three suggested for the shared server. On that server, `gemma3`, `medgemma` and `llama3:70b-instruct` have no tool support in Ollama.
- `.dev/roadmap.md`: MCP host entry at Phase 0.

Phase 0's spikes ran on local Ollama, and their results changed the MCP host plan before any `mcp-client` code exists.

- `.dev/docs/mcp-host/`: spike scripts, a README and `phase0-results.md`. Raw output in `results/` is gitignored and recreated by the scripts. Tool results come from a synthetic catalogue, so no dataset records are involved.
- `.dev/docs/mcp-host-plan.md`: S2 and S5 confirmed. Cancellation is decided by the caller's own signal, since the SDK reports an abort like a timeout.
- `.dev/docs/mcp-host-plan.md`: Ollama's 4,096-token default window truncates silently, so host-core manages the window: `chat` and the UI shorten old tool results in what is sent, and `eval` fails the run.
- `.dev/docs/mcp-host-plan.md`: Ollama drops some calls rather than reporting them malformed, so empty replies are their own class, `empty_reply` (open question 6 asks what follows one). Replies cut off at the output limit are retried once outside `eval`.
- `.dev/docs/mcp-host-plan.md`: smaller provider rules: explicit `temperature` and `top_p`, a configurable `chat` reply cap, and a decision on the `openai` package at the start of Phase 2, since `OPENAI_CUSTOM_HEADERS` cannot be blocked. Question 5 settled: `reasoning` is stored, and sent back only when configured.
- `.dev/tech-debt.md`: `execute_query`'s untyped `sqon`, `combination` required for one clause, and a stale comment on `bind`; the pretty-printed JSON entry gained a token measurement.
- `.dev/roadmap.md`: Phase 0 run locally; Phase 1 can start, since its spikes need no model.

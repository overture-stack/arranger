The Usher adapter follows the module rules and the comment rule.

- `modules/usher-adapter/src/`: a file built around one export is named after it: `accessControlEvents.ts`, `conditionProblemsOf.ts`, `enforcementProblemsOf.ts`, `indexProblemsOf.ts` and `requesterOf.ts`, their tests renamed with them, and `createBridgeLogger.test.ts`. The surface types are in `types.ts`, and `index.ts` holds named re-exports alone.
- `modules/usher-adapter/src/testing/`: the test support, formerly `fixtures/`, is a module with its own index and `types.ts`, its factories named after their exports, and outside the release build. The adapter's suites and `integration-tests/server`'s `usherAdapter` and `categoryParity` suites import it through its index alone.
- `index.test.ts`, `testing/index.test.ts`: each index's runtime exports are pinned against a written list, and every relative import under `src/` reaches another module only through its index, a source file never through its own.
- Comments and TSDoc state what the code is for, how and why, without who calls it, what runs around it, or the adapter naming itself.
- `.dev/roadmap.md`: where shared test support lives, since no other module keeps a set like the adapter's `testing/`.

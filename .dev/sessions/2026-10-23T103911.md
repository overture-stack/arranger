The Usher adapter's branch is rebased onto main's GraphQL error rule, download route rules, loopback route tests and whole-day date reading, each of its commits carrying only what main lacks.

- `modules/usher-adapter/src/conditionFields.ts`, `integration-tests/server/harness/categoryChecker.ts`: a date alone is accepted again as a single range bound in a category condition, covering its whole UTC day, since the GraphQL router now reads one that way on every date field; the checker models it so.
- `modules/graphql-router/src/indexProbe.ts`, `modules/usher-adapter/src/indexChecks.ts`: the index probe counts, in one search with no script, the records holding a field and the values they hold in it, and the adapter refuses a catalogue whose resource field holds more values than records, saying some records hold more than one value. The search engine role no longer needs inline scripts (`modules/usher-adapter/README.md`, `docs/reference/07-feature-flags.md`).
- `modules/graphql-router/README.md`, `CHANGELOG.md`: the `onIndexMapping` hook's second argument, the `IndexProbe`, and its three questions.
- `modules/graphql-router/src/accessControl/AccessControlError.ts`, `filterCallback.ts`, `graphqlRoutes.ts`, `download/index.js`, `network/resolvers/aggregations.ts`: a filter callback may throw `AccessControlDeniedError`, given the catalogue and a kind (`no-access`, `access-too-broad`, `misconfigured`), to deny a read its catalogue before any search. Every read path answers with the GraphQL router's fixed text for the kind, naming the catalogue: `ACCESS_ENFORCEMENT_DENIED` and `403` for `no-access`, `INTERNAL_SERVER_ERROR` and `500` otherwise, logged as `access_enforcement.denial_answered` at info or at error.
- `modules/usher-adapter/src/createUsherAccessControl.ts`: a deny throws that denial, `no-grants` as `no-access`, `filter-limit` as `access-too-broad`, and the configuration reasons, the bridge's own fault and a catalogue missing from the results as `misconfigured`; `access_enforcement.denied` keeps the reason.
- `apps/search-server/src/server.accessControl.test.ts`: every principal is given the same catalogue listing and introspection, without the bridge being asked who is asking, so naming a denied catalogue names only one already listed.
- `.dev/docs/arranger-auth/usher-adapter.md`, `modules/usher-adapter/README.md`, `modules/graphql-router/README.md`, `docs/reference/07-feature-flags.md`, `CHANGELOG.md`: a denial is ambiguous below the catalogue and named at the catalogue, with the reason, kind, code and status of each deny.

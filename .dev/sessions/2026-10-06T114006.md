`.dev/docs/arranger-auth/usher-adapter-tests.md`: the plan states the adapter interface agreed from both sides. A catalogue that fails to load is registered and never verified, so it serves nothing while the others serve normally, with a startup row and an inversion for it. The adapter's new package needs no migration-guide section. The three review items these settle are removed.

`integration-tests/server/harness/parity.ts`: the access parity suite's GraphQL router start-up, its readers for every read path and its spread of client queries move into a harness shared with the Usher adapter's parity suite, outside `test/` so the runner never counts it as a suite. The spread is built over a fixture's own field names and values, each request can carry headers such as a credential, and the router can be served behind handlers mounted ahead of it. The text search in the spread matches any value, `*` where it matched any single character, the same records on `accessParity.test.ts`'s one-letter values.

`.dev/docs/arranger-auth/usher-adapter-tests.md`: a fifth change outside the adapter gives the GraphQL router a second refusal, `AccessControlUnavailableError`, carrying a text and a `Retry-After` value, so a suspended principal's export answers 503 before any row is read and a write answers a GraphQL error coded `ACCESS_CONTROL_UNAVAILABLE` with null data. It is logged as `access_control.unavailable`, never as `access_control.evaluation_failed`, and the plan states how the three refusals differ in the log. The adapter's copy of the bridge's 503 text and `Retry-After` is pinned against the bridge's own.

`.dev/docs/arranger-auth/usher-adapter-tests.md`: every clause of a compiled access filter carries boost 0, so access restricts results and never changes their order; a router unit test pins it, and an inversion holds the ordered parity rows to it.

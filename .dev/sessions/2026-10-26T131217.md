Brought the stashed `modules/mcp-host-core` onto `main` and built what #1105 and #1106 decided, short of how a conversation keeps servers apart.

- `modules/mcp-host-core/src/host.ts`, `src/state.ts`: each server is marked `authenticated` by the consumer, required, never inferred from headers; state keeps every server the conversation has held, with what each returned (`none`, `unauthenticated` or `authenticated`, which only rises), kept after a restore drops the server since its data is still in the conversation; a restore refuses a configuration that adds a server to a conversation holding authenticated data, or unmarks one that returned it (`ServerSetError`)
- returned data means a call ending in a result or a rejection, whose text reaches the model, or a fetched prompt; carried content marks nothing, being the person's own
- the approval policy sees each call's authentication and every server's record, and may return `{ refuse: reason }`, whose tool message names the server and passes the reason to the model; host-core enforces neither way (a) nor (b)
- a new conversation may start from carried content, labelled as server text, with a `content_carried` event
- `src/providers/openAiCompatible.ts`: Chat Completions on `eventsource-parser` 3.x, the line the MCP SDK already installs; the key is a value or a function called before each request, and a 401 is reported, never retried; with `ollama`, the loaded window (`/api/ps`) and digest (`/api/tags`) are read natively, and a run uses the smaller of the configured and loaded windows; a malformed call sent back in history has its raw text wrapped as `{"unparsed": ...}`, since a server may refuse arguments that are not an object
- `package.json`: `"license": "AGPL-3.0-or-later"`, per the plan's licence recommendation

An empty combination in a SQON now means every document wherever it sits, and an access-control filter holding one is refused; export and access-control errors tell their reader what they can act on.

- `modules/graphql-router/src/accessControl/requireServerSideFilter.ts`: a server-side filter is refused when it holds anything that would match broadly where nobody meant it to: an empty combination anywhere, an `all` with no values, which the compiler reads as one, a range with no bound, a `not-in` or `some-not-in` that lost its value list, a clause naming no field, or an entry that is not a SQON node. The refusal names the part and its position, never values, with advice to remove it or deny with a filter that matches nothing. The filter is checked as the callback returned it, before any client filter is combined with it. Every other shape a deployment's filter uses today is served as before, a `null` in a value list and an exclusion with an empty value list included.
- `modules/graphql-router/src/mapping/utils/compileFilter.js`: with no client filter, the composed filter holds the server-side filter alone, adding no empty combination of its own.

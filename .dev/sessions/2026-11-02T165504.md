Worked through a review of `mcp-host-core` so that the module can stand on its own once it moves out of this repository: no references into `.dev/`, shared helpers and named vocabularies, and `McpHost` split into a run, its connections and its tool calls, with the public API unchanged apart from the new constants.

- `modules/mcp-host-core/src/`: kept each type in the file of the domain that owns it, rather than gathering them in a `types.ts`. The import graph has no cycles, `provider.ts` and `events.ts` are already files of types alone, and a central file would become a hub that every module imports
- `modules/mcp-host-core/src/constants.ts`: used `as const` objects rather than TypeScript enums. Checked with `tsc` 5.9: a typo in an annotated return, or in a comparison against a typed value, already fails to compile, while one in a comparison or `case` against `unknown` (the approval policy's decision, a saved state's fields) does not, and a string enum rejects a plain literal, which would break consumers that pass one
- `modules/mcp-host-core/src/utils.ts`: kept host-core's own `isRecord` and `errorMessage` although `mcp-client` has the same helpers, since `mcp-client` does not export them and the two publish separately
- `.dev/tech-debt.md`: added three host-core entries: servers ordered by when they connected rather than by configuration, between-turn surface reads that never reconnect, and a policy's `deny` worded to the model as the user declining; the export-trimming entry now covers the new constants

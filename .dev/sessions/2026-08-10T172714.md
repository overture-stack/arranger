# Session 2026-08-10

## Usher plugin design document

Created `.dev/docs/usher-plugin.md`: Arranger-specific design for the usher-arranger PEP plugin. Covers:

- Terminology mapping between Usher generic terms and Arranger domain terms (Resource -> Catalogue, etc.)
- Grants payload structure (Arranger-relevant fields only; link to Usher security-workflow.md for full spec)
- Core translation algorithm: subtract the token's `categories` include-list from the full sensitive category set declared in catalogue config; generate SQON exclusion expressions for the excluded categories; AND into every query as a server-side filter
- Integration point: Express middleware in the graphql-router
- Mock-first implementation approach: enforce mock grants tokens before building the actual Usher server, to validate enforcement logic from the consumer side first
- Open questions: category-to-SQON mapping format, absent resource handling, anonymous access, multiple catalogues, logging

Deduplication audit: content specific to all plugins (absent resource handling, existence-denial invariant) was added to Usher's plugin-integration.md rather than duplicated here; the arranger doc links to it.

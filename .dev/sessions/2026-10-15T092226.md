Refinements to the MCP host and `mcp-client` documentation, and how concurrent runs in one conversation are limited.

- `modules/mcp-client/README.md`: the options table gives each option's type, whether it is required, and its default; it now states that leaving out `onError` drops background errors, and leaving out `changeNotifications` opens no stream
- `.dev/docs/mcp-host/mcp-host-plan.md`: one run per conversation stays, and a save based on an older version fails rather than overwriting a newer one; §5 question 8 proposes forking a notebook from a cell instead, since two runs at once would split the history, and keeping only the latest branch would lose queries that already ran against controlled data
- `modules/mcp-client/docs/architecture.md`: each section names the test files that cover it rather than individual tests, whose names go stale on a rename
- `.dev/docs/mcp-host/architecture.md`: "Instances and concurrency" shows two researchers' conversations, each with one client per server, and a table of what runs at the same time and why, in place of an entity diagram whose symbols contradicted its labels

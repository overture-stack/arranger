Added a liveness route to the MCP server, so it can run behind Kubernetes HTTP probes, which dial the pod IP and so never pass the Host guard.

- `apps/mcp-server/src/http/server.ts`: `GET` and `HEAD` on `PING_PATH` answer `200` with the search server's ping body, ahead of the Host and Origin guards and before the body is read, and check no dependency. The unguarded route stays liveness only: a readiness route reporting dependency state goes behind the guards and the bearer check, or answers a status code alone
- `apps/mcp-server/src/utils/config.ts`: new `PING_PATH` (default `/ping`); startup refuses one not starting with `/` or equal to `MCP_PATH`
- `apps/mcp-server/README.md`, `apps/mcp-server/.env.schema`, `CHANGELOG.md`: the new variable and route

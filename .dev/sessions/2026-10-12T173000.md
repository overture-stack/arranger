Fixes to `modules/mcp-client` from a review of Phase 1 of the MCP host plan.

- `modules/mcp-client/src/confirmationLoop.ts`: a malformed input request is `input_failed`, and an unexpected error inside the loop is `transport_error`, so a call never rejects
- `modules/mcp-client/src/outputValidation.ts`: output schemas compile once per snapshot on a fresh Ajv instance, so none accumulate or collide across servers; a schema over 64 KiB or 32 levels deep is not compiled, and its tool's results are `output_invalid`
- `modules/mcp-client/src/client.ts`: credentials are refused over plain HTTP except to loopback, unless `allowInsecureHttp` is set; `onError` receives background errors, and a throw from it is contained; `responseCache` is removed, since nothing read it
- `modules/mcp-client/src/surface.ts`: canonicalization is iterative, so a deeply nested surface hashes without overflowing the stack
- `modules/mcp-client/src`: tests use `suite`/`test` and `z as zod`, and now cover resources, an `AuthProvider` retry, a failed connect, background errors and the schema limits; 68 tests
- `.dev/docs/mcp-host-plan.md`: auth, output validation, background errors and `transport_error` (its kinds and tool message) updated; stale cache-bypass reasons dropped; the OAuth and cache-partition claims removed; §5 question 2 notes what resuming a call needs
- `.dev/tech-debt.md`, `.dev/docs/mcp-host-plan.md`: two `modules/mcp-client` hardening entries, which block publishing the module in Phase 5

Adopted agentics 0.19.0, whose two breaking changes are tier moves rather than rule changes, and one of which invalidates part of a global instruction rather than anything in this repository.

- **The dispatch table was missing `git.md` and `initialization.md`.** `git.md` is new in 0.19.0: `session-discipline.md` carried roughly 48,000 characters and the git and commit rules were split out of it into their own file, leaving zero git sections behind. `initialization.md` already shipped and the canonical table already listed it, so its absence here was a longer-standing gap rather than part of this release. Both rows added verbatim from the canonical table rather than paraphrased, and the tag moved to `0.19.0 | synced: 949de721`.
- **The tier move breaks an instruction that lives outside this repository, which no project-file check can see.** A global instruction naming what `session-discipline.md` covers listed git and commit rules and tech-debt entry formats among them; both left that file in this release, to `git.md` and `entry-formats.md`. Following such an instruction literally now silently misses both. Recorded because the class matters more than the instance: **a convention file splitting apart invalidates every external pointer that described its contents**, and the upgrade procedure's own project-file checks cannot detect that, since nothing in them diffs an agent's global context against anything.
- **The commit stamped as `synced` carried an amend signature and was stamped anyway, deliberately.** `949de721` was committed minutes before the check ran with an author date eleven days earlier, the pattern that marks a rewritten commit, and it will orphan if it is amended again. It is the last released commit and is reachable from the canonical remote, which is what the rule requires. The version is the durable half of the marker and the SHA is a cached lookup, so an unresolvable SHA later is a signal to re-derive it from the version rather than an error.
- **Verifying the upstream clone found the remote names inverted against what the check assumes.** `origin` points at a personal fork and the remote named `softeng-fork` is the documented canonical repository, so a comparison trusting `origin` by name would measure against the fork. The comparison was run against the canonical remote instead: zero ahead, zero behind. Worth knowing for any future check in that clone, since the misleading name is in the clone rather than in the convention.
- Several 0.19.0 entries originated in this project's own sessions during the preceding week, including the one-derivation-one-owner rule, the comment-accumulation finding and its generalized form, three session-file gaps, and the runtime-handle report. Noted only because it means much of this release was already being followed here before it was adopted, so the adoption is closer to a formal catch-up than a change in behaviour.

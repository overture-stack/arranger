`main` gains the backwards-syntax rewrite and the adapter test plan's alignment with the built bridge, on top of the pushed agentics adoption, with `.dev/docs/mcp-platform-testing.md`'s three overlapping clauses rewritten in its current text. The Usher adapter branch is rebased onto them.

The Usher adapter's tests, written from Usher's side and reviewed from Arranger's and Usher's, are in place ahead of the code they specify: the startup, callback and logger-shim suites in `modules/usher-adapter/src/`, with their fixtures; the suites through the GraphQL router in `integration-tests/server/test/usherAdapter.test.ts`; the image's startup under access control in `apps/search-server/src/server.accessControl.test.ts`; and the image's default export row limit under access control in `localEnvs.test.ts`. The log-event suite lands with the logging that makes it pass. The adapter's tests resolve the two Usher packages from a tarball install at the repository root until both are published.

The integration suites pass on Elasticsearch 7.17 and on OpenSearch 2.17, 384 each, with Express 4.22.3 and the shared parity harness.

`.dev/docs/arranger-auth/usher-adapter-tests.md`: with access control on, the image reports not ready while the bridge is cold, and otherwise lets the catalogues' status decide readiness, the bridge's uncertain mode included, since the open tier keeps serving through it; the liveness route never depends on the bridge. An inversion holds the uncertain row to it.

`modules/graphql-router`: a facet that does not filter itself removes its own field's clauses from the caller's filter alone, compiled apart as `clientSideQuery`, and restates the server-side filter whole, where the release candidates removed them from both and could drop an alternative of the server-side filter's `or`, counting fewer documents than a search returned. A third full-grant variant in `accessParity.test.ts`, granting every resource through clauses some records meet more often than others, failed 11 rows on both engines before and passes all 73 after; the same variant shows an access filter leaving the order of results unchanged, since every clause it compiles carries boost 0. `router.test.ts` moves its global-aggregation precondition to the test with a client filter on the facet's field. The CHANGELOG records the fix under a new "Fixed since the 3.1 release candidates" section, and the adapter test plan adds the change and a per-endpoint row for a catalogue mapping no category values.

`modules/graphql-router`, `modules/types`: a filter callback receives `{ readPath }` as its second argument, naming the read it serves among `hits`, `aggregations`, `sets`, `export` and `network`, and every read path's context carries the request's own `res.locals` as `locals`, set after every spread on the GraphQL path; an export given `ctx: res.locals`, the router's own `/download` included, carries it the same way. A callback throwing the new `AccessControlUnavailableError` refuses a request for now: GraphQL answers its text with `extensions.code` `ACCESS_CONTROL_UNAVAILABLE`, `/download` answers `503` with the text and `Retry-After`, and neither logs `access_control.evaluation_failed`. `arrangerRouter` takes an `onIndexMapping` hook, called with a copy of the fetched mapping before it resolves, a throw failing its construction. The README documents the four, and the CHANGELOG lists them under Access control.

`modules/usher-adapter`: the adapter translates each catalogue's enforcement result into its GraphQL router's filter. `createUsherAccessControl` gives one callback per catalogue and one `verify`, which checks each loaded catalogue's resource and category fields against its index mapping, keywords outside any nested mapping, before registering every configured catalogue with the bridge in one call, a catalogue that failed to load serving nothing. A narrowing's filter is returned unchanged, `allow` returns the router's allow-all value, and a deny or a missing result matches nothing on the resource field; a suspended principal is served the open tier on hits and aggregations and refused for now on every other read, and network search is refused as a configuration failure. The callback logs `access_control.permitted`, `access_control.denied` and `access_control.unavailable`, and `createBridgeLogger` writes each bridge or adapter event as one JSON line. The unit suite passes 63 of 63 and the integration suite 92 of 92, on Elasticsearch and on OpenSearch, and the row holding routers mounted ahead of the bridge to a configuration fault turns red when a missing store is answered with a deny.

`apps/search-server`: with `ENABLE_ACCESS_CONTROL=true` the image applies the Usher adapter. It reads each catalogue's `usher.json` apart from the configuration merged for its router, refuses startup for a catalogue lacking one or configuring network search, builds the bridge from `USHER_APPLICATION_KEY`, `USHER_AUDIENCE`, `USHER_CONTROLLER_URL`, `USHER_EVENT_SOURCE`, `USHER_ISSUER` and the optional `USHER_PAYLOAD_VERSIONS` unless a host hands it one through its `usher` option, and loads the Usher packages only then. Each catalogue's router gets the adapter's callback and hands its mapping to `verify` before the bridge starts and the server listens; the liveness, readiness and introspection routes answer ahead of the bridge's layer, every catalogue route and the body parsers behind it, and readiness answers `503` while the bridge is cold. Every request carries a server-generated `res.locals.requestId`, an unset `DOWNLOAD_MAX_ROWS` bounds exports at 100 rows under access control, and `arrangerServer` resolves once the server is listening. `.env.schema`, the feature flags page, the migration guide's `ENABLE_ACCESS_CONTROL` section and the CHANGELOG describe it.

`modules/usher-adapter`: an enforcement result or a registration of a kind the adapter does not know is refused by the adapter itself, the callback throwing and `verify` naming the catalogue, rather than left to the router's guard. The README says why a keyword sub-field of a multi-field is refused at startup, and the adapter test plan names the settled event field set.

`.dev/docs/arranger-auth/usher-adapter-tests.md`: the row for a catalogue mapping no category values is a property check: a canonical narrowing cannot reach the facet undercount, its bare resource test being the `or`'s only alternative, so the fix's coverage is the GraphQL router's own facet and parity suites, red without it.

Closed four access-control prerequisites that needed nothing from Usher, and corrected the plugin design's central premise. What each change was is in its commit; this records only what the commits and the code do not carry.

- The terminology table was the highest-leverage instance of the resource-equals-catalogue premise, not an incidental one: a table is consulted out of sequence, so it won every disagreement with the corrected sections fifty lines below it. Correcting the sections first left every one of them reading as inconsistent.
- The `404`-for-an-absent-resource decision was withdrawn on a stronger basis than being superseded: catalogue existence is published unauthenticated by `GET /introspection`, so the disclosure the `404` was buying was never a secret. Reopened rather than amended, because it had been resolved on a false premise.
- `stringToBool` resolving an unrecognized value to the restrictive side was proposed and deliberately not taken. An unrecognized `DISABLE_*` hardening itself to `true` turns a typo into a production outage with a non-obvious cause; the warning supplies the operator signal without changing what any flag resolves to, so no correct deployment behaves differently.
- Asserting a clause's **polarity** rather than its presence is what makes the filter fixture mean anything. Inverting the provenance ceiling from `not-in` to `in` fails three assertions; the presence-based version passed all three, and `getDefaultServerSideFilter` itself emits a `terms` clause that a presence check counts.
- Deferring the nested-field fixture was justified by a claim that did not survive checking: the `should`-for-`must` defect is on the aggregation path, not the record path the fixture exercises, so nothing was blocked and two ordinary passing tests were available. The record path is now pinned as correct, which gives the eventual reconciliation a target rather than a note.
- `SERVER_PORT=0` binds a random port but is not usable, since the listen log reported the configured value and nothing read `server.address()`. Fixed, and a repo-wide default of `0` was rejected: `docker-compose.yml` publishes `5050:5050` with no `SERVER_PORT` set, both Dockerfiles `EXPOSE 5050`, and the v3.1 migration table documents that default.
- `PING_MS` had been dead config rather than absent, so wiring it was recovering an intended feature. `indices.exists` was chosen over a cluster health call because it needs no cluster-level permission, which keeps the application credential as narrow as the startup-health-check roadmap item wants it.
- Completeness of a document index needs a count against the filesystem, and the count needs a definition of "indexed". Treating any mention anywhere as reachability found three of nine unreachable files; requiring a link from the index found all nine. Too permissive hides orphans and too narrow invents them, and only the second is self-correcting, since a false orphan demands an action while a false clean result closes the question.

The CRE ships as a desktop app rather than a hosted web UI, and the MCP host plan follows that decision.

- `.dev/docs/mcp-host/mcp-host-plan.md`: `cre-server` becomes `cre-backend`, the app's backend process; each user configures their own model provider and key, with the team's Ollama reached over their own SSH tunnel; a single-instance lock keeps one run per conversation; a shared `apps/mcp-server` needs TLS and auth, while a loopback one for testing needs neither; §5 adds Electron or Tauri, stdio servers, and controlled data stored on researchers' machines
- `.dev/docs/arranger-auth/mcp-host-connections.md`: the host signs in as an OAuth public client, and every installed copy shares one `clientId`
- `.dev/tech-debt.md`: the two `mcp-client` hardening entries block shipping the desktop app, since users can add their own servers; the confirmation-binding entry names the shared `clientId` as its case
- `.dev/docs/mcp-host/architecture.md`: the system context shows the desktop app on the researcher's machine, with the user's keys and tokens in the OS keychain, and sign-in as a public client
- `.dev/docs/mcp-host/README.md`: the spike scripts move into the evaluation harness's tests when it starts; Phase 1 took none of them, since `mcp-client` tests against its own in-process server

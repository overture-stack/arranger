Continued refining the uncommitted partial-availability work and fixed apps/search-server's five pre-existing TypeScript baseline errors, three of which traced to real type-modeling gaps in shared packages rather than local workarounds.

- `modules/graphql-router/src/searchClient/classifyCatalogueFailureReason.ts` (new), `modules/graphql-router/src/index.ts`, `apps/search-server/src/availability/`: catalogue-failure classification moved into `modules/graphql-router` and exported publicly, since only that package has direct knowledge of the ES/OS client error shapes it classifies. `apps/search-server/src/availability/` now holds only the server-wide aggregate status, exposed through a new barrel (`availability/index.ts`).
- `apps/search-server/src/configs/catalogueId.ts`, `introspection/serverDetails.ts`: `ConfigsObject` generic usage fixed to supply its required type argument.
- `apps/search-server/src/configs/fromEnv/localEnvs.ts`: an unrecognised `SEARCH_ENGINE` env value now logs a warning and falls back to auto-detection, instead of being silently trusted as valid via an unchecked type assertion.
- `modules/types/src/configs/index.ts`: `TableConfigs.columns`, `FacetsConfigs.aggs`, `SetsConfigs.index`/`type`, and `ChartConfigs.query` are now optional. None are validated by `arrangerRouter`'s own config validation and all are fully defaulted by its fallback-config merge, so requiring them from callers didn't match actual behaviour.
- `modules/sqon/src/index.ts`, `apps/search-server/src/introspection/types.ts`: `VersionedSqonJsonSchema` (and its component types) now exported from the sqon package root; the SQON introspection response's `schema` field references it directly instead of a duplicated, looser type.
- `modules/graphql-router/src/mapping/extendMapping.ts`: `extendFacets`'s `aggs` now gets the same defensive `?? []` handling `extendColumns` already had for `columns`. Both functions' log messages corrected from "first 5" to "first 10" extended fields, matching what the code has always actually taken.
- `docs/usage/01-arranger-configs.md`: documents that `table.json`'s `columns` and `facets.json`'s `aggregations` are both optional, with the actual fallback behaviour when either is omitted.
- `apps/search-server`: typechecks cleanly; all 5 pre-existing baseline errors resolved.
- `.dev/tech-debt.md`: logged a real bug found while tracing `SetsConfigs` consumers: `modules/graphql-router`'s Sets query filter reads `INDEX` for both the `index` and `type` ES query fields.
- `CHANGELOG.md`: added entries for the config-optionality fix and the sqon type export.

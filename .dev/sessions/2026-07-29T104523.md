New `FALLBACK_LABEL`/`isFallbackLabel` (exported from `graphqlRoutes.ts`) suppress the label clause entirely from log lines when no identifier is available, e.g. a third-party server embedding a single catalogue with no multicatalogue context.

A catalogue whose GraphQL schema or endpoint failed to build was being silently mounted as `available`, since `arrangerRoutes` (`graphqlRoutes.ts`) swallowed that failure and returned a generic 500-responding handler instead of propagating it; found by inspecting a real production log where a catalogue's schema build threw a GraphQL syntax error but still showed as `available` in the mount summary.

- `modules/graphql-router/src/graphqlRoutes.ts`: `arrangerRoutes` gains an opt-in `rethrowOnError` option (default `false`, preserving today's contract for direct callers of the public `getGraphQLRoutes` export); `router.ts` passes `rethrowOnError: true`, so `apps/search-server` now correctly classifies and reports this failure as `failed` instead of `available`.

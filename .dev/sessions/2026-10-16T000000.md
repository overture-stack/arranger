Decided the desktop app's framework, after reproducing the Tauri flaw that rules Tauri out, and decided the token-exchange trust model.

- `.dev/docs/arranger-auth/mcp-host-connections.md`: Usher's rule B decided: a sign-in token is accepted only by the application it is addressed to, enforced per client via a Keycloak audience mapper set at registration, failing closed when a client's mapper is missing. Decided a deployment holding controlled data permits only an operator-run `apps/mcp-server` to receive tokens addressed to the search server, since it can be revoked, throttled, or watched; a deployment holding nothing controlled may also allow a local instance using the desktop app's own public-client token, at the cost of an actor in the audit trail that is claimed rather than proven. Documented that a local instance holding a token needs either stdio transport or its own Origin validation plus per-connection authentication, never a bare loopback port, since a no-auth target's loopback pattern is only safe because no token is involved there.
- `.dev/docs/mcp-host-plan.md`: decided the framework is Electron, not Tauri, and decided `chat` also ships as a standalone binary. Resolved the TUI library question: Ink is cleared for use, since the Yoga/WASM bundling risk that originally motivated caution no longer exists in the version this project would ship. Resolved the Tauri sidecar question by direct reproduction: Tauri signs every sidecar with the main app's own entitlements, with no option to scope them separately, and a restricted entitlement on the main app kills the sidecar at launch while the build and `codesign --verify` both report success. A Node-based sidecar additionally needs the JIT entitlement once hardened runtime is active, which today it receives only as a side effect of the same unscoped inheritance that causes the crash, so the fix and the defect share one root cause. The packaging tool for `chat`'s own standalone binary is left open between Bun and Node's `--build-sea`, both confirmed genuinely single-file; `pkg` is ruled out for this purpose, since its output is a binary plus a required external data file plus a required environment variable, not actually single-file.

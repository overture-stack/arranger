The GraphQL error rule moves to main ahead of the Usher adapter work, which builds on it.

- `modules/graphql-router/src/graphqlRoutes.ts`, `utils/serverProblem.ts`: a GraphQL error carries only its message, locations, path and code, debug mode included. A request's own mistake keeps its message and code, the router's filter rules under `BAD_USER_INPUT`, logged as `graphql.invalid_request` at info; every other failure is answered with fixed text naming a problem on the server and logged as `graphql.failed`.
- `modules/graphql-router/src/searchClient/clauseLimit.ts`, `mapping/utils/esSearch.ts`, `utils/getAllData.js`, `download/index.js`, `accessControl/AccessControlError.ts`: the engine's refusal of a query past its clause limit is answered, where a server-side filter restricts any record, as `ACCESS_CONTROL_QUERY_TOO_LARGE` naming the catalogue (a 500 on the export route) and logged with the limit, and otherwise as the rule the request's filter broke. Where a server-side filter restricts any record, every search sends `allow_partial_search_results: false`, so a shard refusing it fails the read.
- `modules/graphql-router/src/network/`: each node's `errors` follows the same rules, a remote node's failure answered with fixed text for its kind and its detail logged as `network.node_failed`.
- `integration-tests/server/test/accessFilterSize.test.ts`: the clause limits each engine applies to an access filter, and the answers above, on both engines.
- `docs/reference/08-Migration/v3.1.md`, `CHANGELOG.md`, `modules/graphql-router/README.md`: the migration section and changelog entry for the error shape, and the README's error answers and export failure table.

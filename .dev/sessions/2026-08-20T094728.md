- Contributed one trap that inversion does not cover, and it is this session's recurring shape again. **An orphaned SHA still resolves locally**, because git retains unreachable objects until gc, so the obvious validation ("does my recorded SHA still resolve?") returns a clean pass on a dead commit that a fresh clone will not have. Demonstrated: `git branch -a --contains` returns empty for the orphan while `git cat-file -t` still answers `commit`. The failure therefore surfaces on a different machine than the one that made the mistake, which makes "never stamp a SHA from unpushed work" a write-time discipline that no later check can substitute for. Where a check is wanted, reachability (`git branch -a --contains`) is the signal that fails correctly; existence is not.

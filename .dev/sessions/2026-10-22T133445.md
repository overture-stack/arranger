MCP host Phase 2: `modules/mcp-host-core` built for the parts the plan settles, with seams where the open docs decisions land (the OpenAI-compatible provider and its auth, the approval policy's inputs and server configuration, and the message and state shapes).

- `modules/mcp-host-core`: new private workspace, `@overture-stack/mcp-host-core` as plan §1 names it, set up like `mcp-client` (tsup through wireit, `tsx --test`, `typecheck`); depends on `mcp-client` only, and on no provider library
- `src/registry.ts`: `mcp__<server>__<tool>` reduced to `^[a-zA-Z0-9_-]{1,64}$`, with an 8-hex SHA-256 suffix over the original server key and tool name when too long; tools whose reduced names collide are all left out; `toModelSurface()` is pure and returns a neutral `{ systemPrompt, tools }`, leaving the OpenAI wrapping to the provider
- `src/provider.ts`: `generate(request, signal)` yields deltas, then one `response` or `error` item, so a model error is data rather than a throw; optional `modelDigest()` and `reduceReasoning()` on the provider, so host-core never names `reasoning_effort`; auth stays the provider's constructor concern
- `src/host.ts`: host-core connects each `McpClient` itself, since the input resolver and the change callback must be its own; a surface that cannot be re-read at run start fails the run, after one reconnect for `ReconnectRequiredError`; call ids are `call-<n>` across the conversation, with the model's id kept beside them; the empty-reply retry uses `seed + 1`; a call the time limit cuts off gets the transport-error wording, not "the user cancelled"
- `src/toolMessages.ts`: a new row, "There is no tool with this name", for a call to a name the registry does not hold; tool messages keep text blocks, a placeholder for other content, and `structuredContent` only when there is no text; state stores the capped text the model got, events the full result
- `src/context.ts`: the latest turn is named by its call ids, since a reply with calls and no text leaves no message between one turn's results and the next (found by the integration test, which a shape-based rule failed)
- `src/answers.ts`: questions are registered before their event is emitted, so a listener can answer from inside it; a question withdrawn by cancellation answers `already_answered`
- `src/state.ts`: `state()` writes every missing tool message at snapshot time: "abandoned" for a call waiting on a confirmation, the transport-error wording for one on the wire, "stopped before this call" for the rest
- `src/testing/server.ts`: host-core's own test server rather than `mcp-client`'s, which its build excludes and whose tools serve the client; it moves with host-core in Phase 5
- `.dev/tech-debt.md`: the private-workspace, `typecheck` and `file:`-rebuild entries now cover `mcp-host-core`
- `.dev/roadmap.md`: Phase 2 in progress

Added an end-to-end chat over the whole MCP host stack, so that Phases 1 and 2 can be checked together against a real Arranger before `mcp-cli chat` or the CRE is built.

- `.dev/docs/mcp-host/scripts/e2e.ts`: an interactive chat through `mcp-host-core` to a running `apps/mcp-server`, search server and ES, with no stubs. It imports host-core from source, so the current branch is what runs, answers approvals and confirmations at the prompt, cancels on Ctrl-C, saves and resumes state, takes an optional system prompt, and logs every event under `results/e2e/`. Kept as a spike script beside Phase 0's rather than as product code, since `mcp-cli chat` replaces it
- Ran three scenarios on `gemma4:e4b` against the seeded `file_centric` index. Asking for the file count and accepting the confirmation ran `list_catalogues`, `get_catalogue_fields` and `execute_query` and answered 486, which matches the search server's own count. Declining the confirmation and denying an approval each reached the model as the right tool message
- After a decline, `gemma4:e4b` invented a count and `qwen3:14b` said the query was still awaiting confirmation. Host-core delivered the server's result unchanged, so the cause sits in how `apps/mcp-server` words a decline. Logged in `.dev/tech-debt.md`
